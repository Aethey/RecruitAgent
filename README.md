# RecruitAgent

[日本語](README.md) | [English](README.en.md) | [简体中文](README.zh-CN.md)

日本での転職活動に向けて作った、ローカルで動く AI 面接・学習ツールです。職務経験の整理、日本語での面接練習、技術知識の復習を一つの環境で進められます。音声面接と音声 Demo は任意の機能です。

MIT ライセンスで公開しています。資料・学習記録・ログイン情報は自分の端末に保存されます。AI を利用するときは、その練習に必要な問題・コード・資料・音声を利用先のサービスへ送信します。

## 主な機能

- **面接準備**：自分の履歴書・職務経歴書・求人票（JD）をもとに、共通質問・技術の深掘り・求人別の質問を準備します。
- **回答と振り返り**：結論、自分の行動、確認方法を整理して伝える練習をします。実際の経験と学習資料を区別します。
- **技術の復習**：アルゴリズム、プログラミング言語、実装上の問題を扱うトレーニング、技術の幅のテスト、知識カードを利用できます。
- **資料と記録の管理**：資料を端末内で管理し、練習の振り返り・復習・バックアップができます。
- **多言語対応**：画面と AI 出力の言語を個別に設定できます。日本語・英語・中国語に対応しています。

## ダウンロードと起動

**Node.js 22.19.0 以上**（npm を含む）が必要です。初回起動では依存パッケージをダウンロードするため、インターネット接続が必要です。起動ごとに Web 用のファイルをビルドします。

GitHub からプロジェクトの ZIP をダウンロードして展開するか、リポジトリをクローンします。プロジェクトのフォルダーで起動してください。

- macOS：`start.command` をダブルクリックします。実行権限が失われた場合は、ターミナルで `chmod +x start.command` を実行します。
- Windows：`start.cmd` をダブルクリックします。
- Linux：ターミナルで `sh start.sh` を実行します。

いずれの OS でも、ターミナルから起動できます。

```sh
node scripts/launch.mjs
```

起動スクリプトが Node.js のバージョンとポートを確認し、必要な依存パッケージをロックファイルに従ってインストールして、ビルド後にブラウザーを開きます。標準の URL は [http://localhost:3000](http://localhost:3000) です。停止は `Ctrl+C` です。

依存パッケージがインストール済みなら `npm start` でも起動できます。環境確認は `npm run doctor`、依存パッケージの更新後は `npm ci --ignore-scripts` を実行してください。

## 初めて使うとき

画面の初期設定は中国語です。「设置 → 语言设置」（設定 → 言語設定）で「界面语言」と「用户语言」を両方 `日本語` に変更して保存すると、画面と新しい AI 出力が日本語になります。既存の資料や AI 出力は元の言語のままです。内蔵の知識カードの本文は「用户语言」に従います。面接の質問・tips・音声フィードバックは、面接ごとの「面接言語」を使用します。

1. 「設定 → 使い始める」を開き、右上の「Codex に接続」を選びます。
2. OpenAI の公式ページで自分のアカウントを認証します。利用できるモデルや上限は、実際のリクエスト結果によります。
3. アルゴリズム・プログラミング言語・学習・チャットはそのまま利用できます。面接練習では、先に「ローカル資料庫」に自分の PDF または Markdown をアップロードします。
4. 「面接練習 → 出題資料」で用途を選び、保存します。「履歴資料 / プロジェクト経験」を少なくとも一つ選択してください。本人の事例と技術学習資料は別の用途に設定します。
5. スキャンした PDF や画像は、先に資料庫で整理して文字を読み取ります。記入用の [テンプレート（中国語）](examples/resume-template.md) も用意しています。

資料の閲覧やテキスト資料のアップロードではモデルを呼び出しません。自動整理・AI 練習・チャットではモデルを呼び出します。コードの評価は静的な評価で、ユーザーのコードは実行しません。

認証画面がブロックされた場合は、認証ダイアログのリンクから開いてください。ローカルのコールバックポートが使えない場合は、ダイアログの案内に従ってコールバック URL を貼り付けます。API キーや OAuth トークンは貼り付けないでください。

## 任意の音声機能

音声機能には、端末内の **Codex CLI** と CLI 側でのログインが別途必要です。[Codex CLI の公式説明](https://developers.openai.com/codex/cli) に従ってインストールし、ターミナルで実行してください。

```sh
codex login
```

「設定 → 使い始める」で音声接続を確認するか、音声 Demo を開きます。画面上部での認証はテキスト機能向けで、CLI のログインとは別です。CLI を利用しなくても、音声以外の学習機能は使えます。

音声機能は実験的な Codex app-server / WebRTC インターフェースを利用します。CLI のバージョン、アカウント、サービス側の権限によって利用可否が変わります。マイクを許可してから録音を開始します。面接では回答の文字起こしとフィードバックを保存します。音声 Demo は録音や字幕を保存しません。通話中の音声は OpenAI に送信されます。

## 設定

`.env.example` を `.env` にコピーし、必要に応じて変更します。起動時に読み込みますが、ターミナルで設定した環境変数が優先されます。相対パスはプロジェクトのフォルダーを基準にします。

| 変数 | 初期値 / 用途 |
| --- | --- |
| `PORT` | `3000`：ローカルサービスのポート |
| `DATA_DIR` | `./data`：学習記録・ログイン情報・資料の原本 |
| `SOURCE_DIR` | `./sources`：既存の PDF / Markdown の互換インポート用。作成は任意 |
| `PI_MODEL` | `gpt-5.5`：初回のテキストモデル。保存済みの選択が優先 |
| `CODEX_BIN` | `codex`：音声機能で使用する CLI のパス |
| `OPEN_BROWSER` | 起動スクリプトでは `1`。自動で開かない場合は `0` |

設定を変更したら再起動してください。ポートが使用中なら `PORT` を変更します。モデル一覧はバックエンド SDK から取得し、画面でモデルや表示対象を選べます。

旧バージョンの `data/state.json` と資料フォルダーは引き続き利用できます。新しい出題資料の選択を保存した後は、その選択を使用します。個人の資料フォルダーは公開コードに含めません。

## バックアップと復元

「設定 → データのバックアップ」から `.json.gz` をダウンロードできます。アプリを停止してコマンドを実行することもできます。

```sh
npm run backup
```

標準では `backups/` に保存します。ファイル名を指定する場合：

```sh
npm run backup -- backups/my-study.json.gz
```

バックアップには学習記録と資料の原本が含まれます。**ログイン情報・Pi セッション・音声ログは含めません**。個人資料を含むため GitHub にコミットしないでください。上限は 512 MB です。それを超える資料庫では、アプリを停止してデータフォルダー全体をコピーしてください。そのフォルダーにはログイン情報も含まれます。

復元先には、まだ存在しない新しいフォルダーを指定します。

```sh
npm run restore -- backups/my-study.json.gz --data-dir ./data-restored
```

形式・チェックサム・ファイルパスを検査し、既存のフォルダーは維持します。アプリを停止して `.env` の `DATA_DIR` を `./data-restored` に変更し、起動後に再認証してください。アップグレード手順は [リリースチェックリスト（中国語）](docs/release-checklist.md) を参照してください。

## 通信ログ

Codex への各テキストリクエスト、音声 RPC、通話状態の変化を `data/logs/codex.jsonl` に記録します。`DATA_DIR` を変更した場合は、そのディレクトリ内の `logs/` に保存します。UTC 時刻、インスタンス・リクエスト・セッション・スレッド ID、モデル、所要時間、結果、機密情報を除去したエラーを確認できます。HTTP レスポンスの `X-Request-ID` で対応するログを検索できます。ブラウザー側の接続・録音・応答・音声確認の状態変化も記録します。

質問・回答の本文、履歴書、音声、画像、SDP、認証情報はログに保存しません。約 5 MB でローテーションし、現在のファイルと過去 3 ファイルを保持します。Git・公開パッケージ・バックアップには含めません。`tail -f data/logs/codex.jsonl` で確認できます。面接回答の本文は従来どおり面接履歴に保存します。

モデルの確認失敗は前回の結果として表示します。今回の通話の接続・音声確認状態を優先し、バックグラウンド処理の 1 回の失敗を通話全体の切断とは扱いません。応答が復旧したら古い通知を消します。

## 開発と公開

```sh
npm ci --ignore-scripts
npm run check
npm test
npm run release:check
npm run release:prepare
```

`release:prepare` は `release/` に公開用フォルダーとチェックサム一覧を生成します。コード・公開文書・確認済みのデモ画像・合成テスト資料・テンプレートのみをコピーします。個人資料・ログイン情報・依存パッケージのフォルダー・未確認の画像・既存の Git 履歴は含めません。このフォルダーから GitHub リポジトリを作成できます。

`.gitignore` は、すでにコミットした機密ファイルや履歴を削除しません。元の作業フォルダーを公開する場合は、[リリースチェックリスト（中国語）](docs/release-checklist.md) に沿って公開対象と履歴を確認してください。

CI は Linux・macOS・Windows を対象としています。実際の結果は GitHub Actions で確認してください。合成モデルのテストはプログラムのロジックを確認するもので、実際のアカウント・利用上限・マイク・実験的な音声接続の動作を保証するものではありません。

サービスは端末内のループバックアドレスだけで待ち受けます。それぞれの利用者が自分の端末で起動する用途です。GitHub はソースコードとダウンロードの提供に利用します。このバージョンは、インターネット上で複数人が接続するサービスには対応していません。

## 多言語リソースとコード生成

画面の文言は `public/locales/zh.json`、`public/locales/ja.json`、`public/locales/en.json` で管理します。3つのリソースは同じ固定キーを使います。文言を追加するときは3言語の訳を記入し、文言を変更するときはキーを維持して対応する訳を更新してください。

```sh
npm run i18n:generate
npm run i18n:check
```

`i18n:generate` はローカルのリソースを読み込み、`src/generated/localizations.ts` に文言のキー・引数型・アクセス関数を生成します。**生成するのはコードです。訳文の生成や、モデル・翻訳サービスの呼び出しは行いません。** 生成ファイルは直接編集せず、CLI で更新してください。

画面では `t('ui.startVoiceInterview')`、変数を含む文言では `t('voice.stats', {seconds, sent, received})` を使います。3言語のキーの不一致、空の訳、プレースホルダーの不一致、生成コードの更新漏れ、画面コードに直接書かれた中国語はチェックでエラーになります。`npm run check` はこのチェックとフロントエンド・バックエンドの型チェックを実行します。

ユーザー資料、回答、コード、保存済みの AI 本文は原文を保持します。

# GitHub 发布检查

推荐从 `npm run release:prepare` 生成的目录建立仓库。该目录只复制应用代码、合成测试资料、公开文档和模板，不复制用户文件、安装依赖或 Git 历史。

## 上传前

1. 运行 `npm run check`、`npm test`、`npm run release:check`。
2. 运行 `npm run release:prepare`，检查输出目录及 `release-manifest.json`。
3. 首次安装需要联网下载依赖。用输出目录完成一次干净安装和空数据启动。
4. 新用户流程：打开设置 → 连接自己的账号 → 上传简历 → 选择出题资料 → 生成练习 → 重启后确认记录。
5. 若上传原工作目录，检查 Git 待提交列表及已有历史：`sources/`、`data/`、`.env`、`screenshots/`、`backups/`、本地开发记录不得出现。`.gitignore` 不会移除已跟踪文件或清理已有历史。
6. 截图只使用虚构或脱敏演示数据。日语、英语和中文 README 共用四张日语界面图片，来自隔离的演示环境，保存在 `docs/images/`，并按具体文件名加入发布清单；`screenshots/` 中的开发截图仍不发布。新增图片时需检查画面与元数据。文件内容检查只识别已知特征，仍需人工检查待公开文件。

## 验证边界

- CI 配置在 Linux、macOS、Windows 上执行安装、类型检查、测试和发布内容检查；实际执行结果以 GitHub Actions 为准。
- 测试中的模型与语音均为合成 fixture，不证明用户的订阅、额度、实验语音接口和麦克风可用。
- 真实账号验证由使用者在自己的电脑上完成，凭据不进入仓库、日志或发布包。
- Node 版本、依赖、CLI 版本变更后，应重新完成安装和启动验证。

## 升级

1. 在设置下载备份，或停止应用后执行 `npm run backup`。
2. 停止旧服务，安装新版本的锁定依赖。
3. `.env` 的 `DATA_DIR` 指向原数据目录，启动应用。原版本 1 数据及未配置资料选择的本地资料目录仍兼容。
4. 若需要回退，将备份恢复到新目录，再启动旧版本；不要用旧版本直接覆盖已升级的数据。
